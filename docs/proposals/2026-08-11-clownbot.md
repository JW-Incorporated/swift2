## 1. What it is

**Clownbot is a chat surface where a fan clowns with the site's own lore.**
"Clowning" is the fandom's affectionate word for knowingly over-speculating —
boarding a theory that may humiliate you later. The self-awareness is the
brand: the bot speculates *in character as a fellow clown*, never as an
authority.

A fan can:

- ask about any egg, clue, symbol, or theory ("what's with the orange door?",
  "is the 2.6-year Karma graffiti gap really the longest?");
- ask what's clownable *right now* ("what are we clowning on this week?") —
  served from the open rumor tier and unresolved theories;
- bounce their own reading off the bot ("here's my theory about track 5…") and
  get a response that grades it **against the sourced record only** ("the
  orange-door part is real — see The Decode — the rest of you is pure clown,
  respect") — conversation-scoped, never stored;
- get walked into the site: every reply cites and deep-links the items it used
  (`/?item=…`, `/?lens=…`), so the bot is a tour guide into Eras and Threads,
  not a destination that replaces them.

## 2. The corpus — the threads ARE the inputs (Joey's directive)

The bot owns no content and invents none. Retrieval draws exclusively from
what the site already authors and fact-checks:

| Input | Today | Notes |
|---|---|---|
| Clue→payoff pairs | 42 `CLUE_PAIRS` in `lib/longlive/lenses.ts` (The Decode) | dated, sourced, `confirmed` flags |
| Egg nodes + motif trails | 30 `EGG_NODES` / 7 `MOTIFS` (The Clue Web) | |
| Fan theories | 60 entries, `theories.generated.ts` | confidence + outcome badges — the "open" ones are the live clown material |
| Rumor tier | Rumor Desk output in the vault (confirmed / rumored / debunked labels, daily-refreshed) | replaces the dead news-pipeline dependency |
| Track dossiers | `tracks.generated.ts` meaning tiers (confirmed / supported / fan-theory) | |
| Vault moments | 728 items incl. cross-links | grounding context |

**When #445 (Mastermind / Invisible Strings) ships its unified case-file
corpus, that becomes the primary input** — this spec is written to consume
either the current three-corpus shape or the merged one, so neither project
blocks the other.

**The hard rule, inherited from Mood Chat:** the model never touches the
corpus directly and cannot invent an egg, theory, rumor, or fact. A
deterministic retrieval layer (keyword/tag/motif matching over the corpora
above) selects the candidate items; the model only writes clowning-voiced
prose *around the items it was handed*, with their labels and links carried
through verbatim.

## 3. Runtime architecture — the Mood Chat pattern, reused

Dynamic route `apps/web/app/api/clown/route.ts`, mirroring
`api/mood/route.ts` stage for stage:

1. **Per-IP rate limit** (same per-instance sliding window).
2. **Deterministic input gate, before any spend:** topic blocklist screen on
   the user's text (§4). A blocked topic returns the fixed redirect copy —
   the model is never consulted.
3. **Deterministic retrieval:** keyword/motif/era matching over the §2
   corpora → top-N candidate items with their labels, dates, links.
4. **Compose (the only model call):** one capped LLM call writes the reply
   around the retrieved items. Over budget or model down → **fallback serves
   the retrieved items as cards with fixed clowning framing lines** — the
   feature keeps working with zero model calls, exactly like Mood's keyword
   fallback.
5. **Deterministic output gate:** blocklist re-screen + "no new facts" check
   (every proper-noun claim in the reply must trace to a retrieved item's
   text; violations drop to the card fallback).
6. **Nothing stored.** The user's text is never written down (Mood's privacy
   stance, same wording on the surface: "what you type isn't saved").

Cost controls, same as Mood: `clown-usage` daily cap per instance (start at
Mood's 200/day, Wyatt ratifies), per-IP rate limit, the console-level API cap
as the real ceiling. No accounts, no DB writes, no notifications.

## 4. Voice and safety — the register IS the safety model

- **Always a clown, never an authority.** Fixed register: self-aware
  speculation ("putting on my clown makeup…"), every claim tagged with its
  source label — **confirmed** (links the payoff), **supported**, or
  **clowning** (pure speculation, and it says so). The bot is structurally
  incapable of certainty about anything unconfirmed: the label comes from the
  corpus item, not the model.
- **Strict topic blocklist (Joey, 2026-08-11 — confirmed unchanged):**
  relationship-existence speculation, health, pregnancy, sexuality,
  family/minors, legal wrongdoing, private individuals. Enforced
  deterministically on input AND output (§3 gates), not by model judgment.
  Blocked topics get an in-character redirect ("that's not my circus — but
  have you seen what the orange door is doing?").
- **UNOFFICIAL framing** carried on the surface, same as the rest of the site.
- **Crisis language check** reused from Mood (`mood-safety.ts`) — if someone
  brings genuinely heavy text to a clown bot, they get the same careful
  handling Mood already ships, not a bit.

## 5. Explicitly out of scope (the #36 line, restated)

No accounts. No storing or publishing user theories. No novelty scoring. No
cross-user anything. No notifications. A future community theory board
remains possible but requires its own decision entry reversing the locked
constraints — this bot neither needs nor advances any of that.

## 7. Definition-of-Done acceptance criteria (item 7 flips 🟢 when…)

- The chat surface ships behind the agreed nav entry, mobile + desktop.
- **Groundedness red-team:** a 50-question adversarial pass produces zero
  invented eggs/theories/facts — every claim traces to a corpus item (the
  output gate's "no new facts" check verified by hand on the transcript).
- **Blocklist red-team:** direct and oblique attempts on every banned topic
  get the redirect, never engagement.
- Fallback verified: with the model disabled, the surface still answers with
  retrieved cards.
- Caps live and tested; kill switch (env flag hides the pill + 503s the
  route) tested once.
- Joey device test; the usual CLAUDE.md per-feature definition of done.
