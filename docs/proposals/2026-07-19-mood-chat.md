# Mood chat — "tell me how you feel, get the songs that fit"

**Status:** approved to build (Wyatt, 2026-07-19). Built in stages by the
`Mood Chat builder` fleet routine, one stage per run, each stage its own PR.
User-facing wording lives in `docs/content-ops/mood-chat-safety-language.md`
and is **founder-gated** — Stage 4 and 5 must not ship until it is approved.

## The shape

```
reader's words ─► Sonnet #1 ─► mood vector ─► DETERMINISTIC ranking ─► top N songs
                  (classify)   (8 axes)       (pure TS, zero cost)          │
                                                                            ▼
                              Sonnet #2 writes the reply ABOUT songs already chosen
```

**The model never searches the catalogue.** It does two small bounded jobs —
read a feeling, and write prose about picks it was handed. Matching is pure
TypeScript over a precomputed index. Consequences, all of them the point:
sub-second responses, deterministic and unit-testable matching, trivial
cost, and **the model cannot invent a song that doesn't exist** — the same
no-fabrication guarantee the rest of the Vault runs on.

## Stage 1 — the catalogue (no UI, no API, no spend)

Generated file `apps/web/lib/longlive/song-moods.generated.ts`, produced by
`scripts/sync-song-moods.mjs` from seeds, guarded by `check:generated` like
every other generated file. Per song:

```ts
{
  slug: 'all-too-well-10-minute-version',
  title: 'All Too Well (10 Minute Version)',
  eraId: 'red',
  youtubeId: '…',              // REUSE TrackNote.youtubeId — per-song audio, oEmbed-verified
  moods: {                      // 0..1 per axis
    heartbreak, anger, nostalgia, joy, calm, defiance, longing, catharsis
  },
  energy: 0.5,                  // 0..1
  valence: 0.15,                // 0..1 (sad → happy)
  useCase: ['crying in the car', 'the 3am spiral'],
  oneLiner: 'Ten minutes of a wound reopened on purpose.'
}
```

**Hard rules.** No lyrics, ever — `safety.redline` auto-files P0 on
verse-shaped text and the redlines ban lyric dumps; mood axes and ORIGINAL
one-liners only. Every song must resolve to a real track in
`tracks.generated.ts`, and its `youtubeId` comes from that track's own
`TrackNote.youtubeId` (the audio-curator flow oEmbed-verifies one per song
against an official Taylor Swift channel — full-catalogue coverage, not just
the ~44 songs the VIDEOS system happens to carry a music video for). A song
whose track still has no verified `youtubeId` ships without one and the UI
omits the embed rather than guessing.

## Stage 2 — populate

Score every track from its EXISTING researched note (`TrackNote.note` +
article body). This is authoring, not runtime: it happens once, offline, and
lands as a reviewable PR. Never invent a fact about a song to justify an
axis.

## Stage 3 — the matcher (still zero runtime cost)

`apps/web/lib/longlive/mood-match.ts`: mood vector in, ranked songs out.
Pure, synchronous, no network. Unit tests assert real expectations —
"heartbroken and angry" surfaces All Too Well / I Knew You Were Trouble;
"content and nostalgic" does not. Diversity rule: don't return five songs
from one era unless the mood genuinely points there.

## Stage 4 — the API route

`apps/web/app/api/mood/route.ts`. Copy Orbit's discipline
(`~/Desktop/Vibe Coding/Orbit/apps/worker/src/classify/claude-client.ts`) —
ONE module that spends money, with:

- **Hard daily call cap**; over it, fall back to the keyword matcher and
  still return real songs (degraded, never broken).
- **Structured JSON output** for the classify call.
- **One retry, then fall back.** Never surface a raw model error.
- **Stable system prompt as a cacheable prefix**, volatile user text after.
- **Per-IP rate limit.** A public unbounded LLM endpoint is a billing
  incident waiting to happen.
- **Crisis check BEFORE matching** — see the safety doc, Block 1. On a
  crisis signal we return the resources block and NO songs.
- **Never log raw user text** — log the derived vector + picks only
  (safety doc, Block 5). We cannot leak what we never wrote down.
- Model: Sonnet (`claude-sonnet-5`). Key: `ANTHROPIC_API_KEY` from env,
  never committed.

## Stage 5 — the page

Its own top-level surface **alongside Eras and Threads** in the top-right
switcher (Wyatt, 2026-07-19) — not buried inside an era. YouTube embeds
reuse the existing click-to-play facade (`youtube-nocookie`, poster only
until tapped) so a results list never spawns players. Mobile-first: this is
a phone feature.

## Stage 6 — tuning

Feed the stored vectors + picks (never raw text) into a quality pass.

## Non-negotiables

1. No fabricated songs — picks come from the catalogue, never the model.
2. No lyrics stored or rendered.
3. Crisis path live before the page is publicly reachable.
4. Raw user text is never persisted.
5. Spend is capped, and the degraded path returns real songs.
