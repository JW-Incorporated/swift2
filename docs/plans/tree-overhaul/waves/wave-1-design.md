## Deliverables — one PR, branch `docs/tree-overhaul-specs`

Seven specs in `docs/specs/tree-overhaul/`, each with these sections in this order: **Behavior you will see** (written for a non-coder founder, ≤200 words, concrete: what appears in Discord, what happens when they react), **Data** (files, schemas, examples), **Mechanics** (which workflow/script/prompt changes, with file paths), **Acceptance criteria** (testable), **Files affected**, **Open questions** (only genuine spec gaps; decide everything reversible yourself and say so).

1. `s3-reason-protocol.md` — reactions ✅ / ✏️ / ❌ on a brief; ✏️ and ❌ require a reply to the brief message from an approver (Discord `message_reference`); poll writes reason to the PR `reject:` comment and to `social/feedback/<ISO-week>.jsonl` (`{ts, pr, file, platform, campaign, pillar, action, reason, originalBody, editedBody?, approver}`); ✏️ applies the reply text as the new caption, recomputes the stamp, keeps both versions; no reply → reaction stays pending, daily digest asks for it; never close a PR on a bare ❌ any more. Define the poll's generic "reaction → action" table so Reddit items (S6) and brief proposals (T4) reuse it.
2. `t1-one-charter.md` — merge Growth into Tree: one charter (`docs/agents/tree.md` absorbs `growth.md`), two runs (weekly plan, daily draft) under one name; rename workflows/prompts (`routine-growth-draft` → `routine-tree-daily-draft`), keep Tier-2 attribution trailers valid; `sourceRoutine` becomes a lane field (`calendar | merch | appearance | reddit`); what "from Tree" means in every surface (Discord username, PR author label, email From).
3. `t2-self-critique.md` — rubric (on-strategy, on-voice, specific, media earns its place, "would I be embarrassed to send this"), 1–5 each, threshold to queue, the two-sentence "why this serves the pillar" that becomes the brief's first paragraph; stored in the queue file (`critique: {scores, why}`) and included in the stamp's hash? (decide: no, so a caption edit doesn't need a re-critique — justify); the Monday run compares Tree's scores to founder outcomes.
4. `t4-weekly-brief.md` — Monday post in `#longlive-social` from Tree: scorecard (5 lines), what changed and why, next 14-day calendar with one rationale line per slot, ≤3 numbered proposals (✅/❌ each), ≤2 questions; founder replies in the message's thread; the poll ingests approver thread replies as comments on Tree's plan PR; Wednesday cut-off triggers a mid-week re-plan run (`workflow_dispatch` from the poll when a new reply lands before Wed 23:59 UTC); the email mailer stays as a copy, not the primary.
5. `t5-lessons-ledger.md` — `social/lessons.md` schema (rule, first seen, evidence links, times fired, status active/retired); Monday distillation from `social/feedback/*.jsonl` + thread replies; strategy changes proposed as a diff to `docs/marketing/social-strategy.md` in the plan PR; rule fired 3× → Tree files an issue to codify in `check-drafts.mjs` (rule 8); the daily draft prompt reads the ledger before drafting and the critique cites the rules it checked.
6. `t6-side-doors.md` — merch-official-sync and appearance-discovery stop authoring captions; they write a `social/inbox/*.json` intent (product/appearance facts, media, deadline) and Tree's daily run drafts them as `fast lane` slots with their own rubric line; the human gate is unchanged; what happens to an intent Tree declines.
7. `t7-autonomy-ladder.md` — per campaign-type eligibility: ≥95% unedited ✅ over the trailing 4 weeks AND ≥8 briefs AND 0 ❌ → Tree may propose "post-and-notify" for that type in the Monday brief; founder ✅ on the proposal writes `social/autonomy.json`; the gate/poller auto-stamps eligible drafts with approver `policy:<type>@<date>`, posts them to the channel as "posted under policy" with a 24h ❌ that pulls the type back to the gate and records a lesson; anything not eligible behaves as today. Include why the human gate remains the default and what would make you (the designer) rule this out.
