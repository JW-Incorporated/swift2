## merch-awin-sync.yml mechanics
cron 53 7 daily + dispatch; timeout 45 (:21). Steps: checkout, setup-repo, sync:content, cache restore (:32-39, key merch-awin-sync-${run_id} with prefix restore-key), sync-awin-programmes.mjs (:44), affiliate-coverage.mjs (:46), open PR (:47-57, branch merch-revenue/awin-advertiser-map), sync-awin-feeds.mjs (:62), upload artifact, cache save (:68-74). Feed loop fetchChangedFeeds (sync-awin-feeds.mjs:130-162) is strictly sequential, sleeps MIN_REQUEST_INTERVAL_MS 12,000 ms between feeds (:22; ~13 s per feed in logs), MAX_FEEDS_PER_RUN 60 (:23), RUN_BUDGET_MS 25 min (:24), idle timeout 120 s (:26), deadline checked only between feeds. Incremental logic exists (compares feed updatedAt against awin-feed-cache.json :76-79) but nextFeedCache (:260) and FTS rebuild (:259) happen only after a successful run, so partial progress is lost on any kill. The loop does not filter by joined status (only !feed.advertiserMid :240).
Proposed fixes: (1) wrap FTS rebuild in BEGIN/COMMIT, or INSERT INTO products_fts SELECT, or external-content FTS; (2) move FTS rebuild out of the feed run or only when something changed, lower RUN_BUDGET_MS so it exits before 45 minutes; (3) write the cache JSON after every feed and add if: always()/!cancelled() to the cache save; (4) pull feeds only for joined: true advertisers (directory shows 0 joined, so idle until a join); (5) parallelism is capped by R5 (12 s interval IS the 5/min limit), so the saving is skipping unchanged/unjoined feeds; (6) drop generatedAt or keep the old value when the advertiser list is unchanged, or stop opening a PR when only that line differs, and find what dispatches every 6 hours.
