## What a "relay" means (explained to owner)
GitHub's servers are blocked/throttled by Reddit. A relay is a small always-on program on a home computer that the GitHub job calls to fetch Reddit pages from the home connection. The repo supports `HOME_RELAY_URL` for this but none is configured. If the Qwen browser tool can serve pages or results over HTTP, it could be the relay.

## Jev, from the official docs (research-jev-docs.md; fetched via a summarizing tool, quotes may be paraphrased)
- Jev is a "System One" decision model by TypeSafe: input text plus typed questions, output typed answers with probabilities. It does NOT write text or code and gives no reasoning. Use it for routing, classification, gating, verification; keep prose and drafting on Claude. (https://docs.typesafe.ai/concepts/system-one)
- Question types: Choice (pick one, up to 255 options, returns probabilities and confidence), Score (2-10 levels), Noul (yes/no probability). Many questions per call run in parallel and in isolation (13 questions: 12.2x cheaper and 10x faster than 13 calls).
- Models: jev-1.14.0 (available now), jev-1.13.0; aliases jev-latest (1.13.0) and jev-preview (1.14.0). Pin an explicit id. Price $0.042 per million input tokens, output free. Context 64k per request, 32k per question (262k with a slower, less accurate long-context header). Cookbook-reported cost about $0.000046 per call, mean latency 114 ms.
- API: POST https://api.typesafe.ai/v1/systemone, Bearer auth, own JSON schema (not OpenAI-compatible): request {state, model, questions:{id:{type, instructions, criteria}}}, response {model, answers, usage}. SDKs: Python `typesafe-sdk`, Node `@typesafe-ai/sdk` (Node 22+ per SDK page, 20+ per quickstart). Env var TYPESAFE_API_KEY. No documented streaming, tool calling, caching or batch endpoint. 429 retried by SDKs.
- Useful cookbooks: confidence-based routing (floor 0.6, auto-act above 0.85, below 0.5 to a human); cascade (cheap extract, Jev checks each field, strong model only if any P(wrong) > 0.7); llm_guardrails (Noul per hazard plus severity Score, thresholds review 0.35, action 0.70); citation_check (exact string match then supports/contradicts/unrelated, confidence under 0.8 to a human) which maps directly to the "confirmed" fact-check bar; classification_using_confidence (confidence >= 0.9 right 27 of 30, below 0.9 right 12 of 30); classifying_rag_passages; parallel_questions; consistency cookbooks.
- Not covered by the docs: voice/style scoring and GitHub Actions use. Voice quality scoring should stay on Claude (or a cheap Claude model).
- Gotchas: unreliable at counting, dates/times, arithmetic and multi-hop reasoning; accuracy drops on large noisy state; injected instructions in the input can shift answers (Reddit and fan text is untrusted, so wrap with delimiters and verify); leans to the first Choice option (randomize option order); Score levels weakly calibrated; calibration holds in aggregate, not per answer; no accuracy benchmark vs Claude or GPT; repeat-run agreement 99.2% on one moderation rubric (not accuracy). Data: commitment not to train on user data (privacy policy), zero retention enterprise-only. Rate-limit numbers, status page, SLA, regions, signup and commercial terms were not found.
- Fit for Swift2 routers (from the token-burn table): marjorie-triage, news-triage, kevin-radar, awareness-answerer triage step, marjorie-ops decision step, marjorie-status-reply classification, community lead scoring, the breaking-news candidate classifier and the "confirmed" source-count check, the media-completeness and redline checks that are judgments, and escalation decisions. It cannot replace drafting routines.
